# Context: 鋒岳自動化 / FORGEON AUTOMATION Demo Site

Single-context repo. This is the one `CONTEXT.md` for the whole project — see
`docs/agents/domain.md` for how the engineering skills should consume it.

## What this project is

A fictional bilingual (zh-TW/en) B2B industrial automation company website —
"鋒岳自動化" / "FORGEON AUTOMATION" — built as a portfolio/market-validation
piece for a design agency ("頁構所"). Astro + TypeScript strict, static-first,
Content Collections for products/solutions/industries/insights. Not a real
company; see the Demo Mode disclaimer rendered on every page.

Full company/product/brand facts live in `PRODUCT.md`. Full visual design
system live in `DESIGN.md` and `docs/DESIGN_SYSTEM.md`. Neither is
duplicated here — this file is for domain vocabulary and glossary terms, not
project narrative.

## Glossary

Terms the codebase and docs use consistently — prefer these over synonyms
when writing tickets, specs, or code comments.

- **Demo Mode** — the `PUBLIC_DEMO_MODE` / `PUBLIC_ALLOW_INDEXING` env-flag
  pair that gates whether the site outputs `noindex,nofollow` and skips
  Schema.org Organization data. Not the same as "development mode" — it's a
  content-integrity gate, orthogonal to `astro dev` vs `astro build`.
- **RFQ** — Request For Quote, the contact form's primary conversion path
  (`ContactForm.astro`). Has a Demo submission mode (never sends real data)
  and a Live mode (real endpoint, currently unconfigured).
- **CC-stage** — a numbered stage (CC-00 through CC-10) in the ongoing
  Precision Datum System redesign, defined in
  `docs/redesign/forgeon_claude_code_redesign_tasks.md`. Each stage has a
  hard scope boundary enforced by the user dispatching one stage at a time.
- **Precision Datum System** — the chosen visual design direction (as of
  CC-01): positioning/inspection/assembly engineering concepts translated
  into a coordinate-system visual language (datum origin, tolerance band,
  vision-lock frame, assembly spine). See `docs/DATUM_DECISION_LOG.md`.
- **Concept Scenario** — a labeled, clearly-fictional walkthrough (problem →
  input → decision → system → deliverables) used in solution/product copy.
  Never presented as a real client outcome.
- **Datasheet** — the per-product PDF spec sheet generated by
  `scripts/build-datasheet.mjs`, downloadable from product detail pages.

### Precision Datum System vocabulary (formalized during CC-01 post-hoc review)

Fixed bilingual terms for the CC-01 visual design language. Use these exact
names in code, comments, tickets, and specs — do not drift to synonyms.

- **Precision Datum System／製程座標系** — the chosen visual design
  direction as of CC-01: positioning/inspection/assembly engineering
  concepts (datum points, coordinate axes, tolerance ranges, vision
  targeting, modular assembly) translated into a coordinate-system visual
  grammar. Governs `src/styles/tokens.css` and `src/components/brand/`.
  Not a general "industrial" or "technical" aesthetic label — it names one
  specific, literal visual grammar (see the six Brand Primitives below).
- **Datum Origin／基準原點** — `DatumOrigin.astro`: an asymmetric
  horizontal/vertical axis pair meeting at a single copper-colored origin
  point, with an optional coordinate label. **Is NOT** a crosshair or
  targeting reticle — the deliberately asymmetric arm lengths (38%/62%
  split) and steel-colored (not copper) axis lines are what keep it from
  reading as a crosshair. Only the origin point and its ring carry accent
  color.
- **Coordinate Axis／座標軸** — the steel-colored line elements that make
  up Datum Origin's and Assembly Spine's structural lines. Not a
  standalone component — a shared visual sub-element referenced by name
  in reviews/specs so "the lines" has one term.
- **Tolerance Band／公差帶** — `ToleranceBand.astro`: two parallel boundary
  lines (min/max) with a translucent acceptable-range zone between them,
  plus optional target and current-value markers. **Is NOT** a progress
  bar — there is no single filled percentage and no start-at-zero fill
  animation; the band's static width is the entire message ("this is the
  acceptable range"), not "how far along a process is."
- **Vision Lock Frame／視覺定位框** — `VisionLockFrame.astro`: four
  L-shaped corner registration marks (machine-vision targeting
  convention) around slotted content, with 0-4 fixed (non-random) feature
  points. **Is NOT** a looping/scanning-effect animation — motion is
  strictly a one-time align→lock→complete sequence triggered once via
  IntersectionObserver; it never repeats or sweeps continuously.
- **Assembly Spine／模組組裝軸** — `AssemblySpine.astro`: a single main
  axis line with 3-6 module nodes in one of three states (unconnected /
  aligned / connected). Represents "modules assembling along one system
  axis" — product assembly sequences, workflow stages, System
  Architecture diagrams.
- **Process Stamp／流程狀態標記** — `ProcessStamp.astro`: a
  rectangular-chip status marker (Reviewed / Evaluated / Configured /
  Verified) with a datum corner notch. **Is NOT** a certification or
  compliance mark — no circular/shield seal shape, no laurel wreath or
  ribbon, always renders the literal words "流程狀態 · PROCESS STATUS" as a
  permanent visible label so it can never be cropped/screenshotted into
  something that reads as a standalone official seal.
- **Cutaway Window／模組剖面視窗** — `CutawayWindow.astro`: an angled,
  non-rectangular media reveal built with `clip-path: polygon()` (not an
  SVG mask), with a labeled technical placeholder when no image is
  supplied.
- **Brand Primitive／品牌視覺元件** — the collective name for the six
  components above, `src/components/brand/*.astro`. Distinct from generic
  UI components in `src/components/ui/` — Brand Primitives carry Precision
  Datum System visual identity; UI components (Button, Card, FormField)
  do not.
- **Concept Project／概念專案** — this entire site: a fictional company
  built as a portfolio/market-validation piece, never presented as a real
  business. See Demo Mode below.
- **Demo Data／示範數值** — sample numeric/label content rendered through
  a Brand Primitive (e.g. `ToleranceBand`'s min/max/target/value props) that
  is not derived from any real measurement. The component that renders it
  does not fabricate the figures itself — it only visualizes whatever the
  caller passes — so the caller is responsible for the `isDemoData`
  labeling being accurate.
- **Engineering Evidence／工程證據** — concept-labeled deliverable
  artifacts (Requirement Sheet, System Architecture, Configuration
  Matrix, Acceptance Checklist) used in place of fabricated case studies
  or client testimonials — CC-03+ scope, referenced here because the term
  appears in CC-01-era docs.
- **Interactive Primitive** — a Brand Primitive usage where `interactive`/
  `animated` is explicitly set true by the caller, enabling client-side JS
  (click-to-cycle on Assembly Spine, IntersectionObserver lock-on on
  Vision Lock Frame). Only meaningful per-*usage*, not per-component — the
  same component file can render as either an Interactive or a Static
  Primitive depending on the props a given call site passes.
- **Static Primitive** — a Brand Primitive usage with `interactive`/
  `animated` left at its default `false`. Must not emit interactive-only
  DOM (e.g. a real disabled `<button>`) or interactive-only ARIA wiring
  when rendered this way — see the CC-01 codebase-design review's
  Assembly Spine finding for a case where this expectation was checked
  against actual output.
- **Locale Message** — text content that varies by site locale (zh-tw /
  en), sourced from a locale-aware caller (page/layout with a resolved
  locale) rather than hardcoded inside a shared component. None of the
  six Brand Primitives currently accept a `locale` or `messages` prop —
  they hardcode Traditional Chinese strings directly. Recorded as a
  disposition in the CC-01 post-hoc review (see
  `docs/engineering/reviews/CC-01-two-axis-review.md`), not fixed this
  round.
- **Design Token Compatibility Alias** — a legacy `--color-*` / `--fs-*` /
  `--space-*` / `--radius-*` custom property (e.g. `--color-accent`,
  `--space-md`) kept in `tokens.css` and re-pointed at the new Precision
  Datum token it now means, so the ten pre-CC-01 components keep working
  unmodified. Not meant to gain new consumers — new work should reference
  `--color-copper-600` etc. directly, per `tokens.css`'s own file-header
  comment.
