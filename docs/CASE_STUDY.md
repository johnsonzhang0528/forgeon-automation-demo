# CASE_STUDY.md

> **概念案例聲明**：以下內容為頁構所（Yegou Studio）市場驗證用的作品集概念
> 案例，客戶「鋒岳自動化 FORGEON AUTOMATION」為完全虛構品牌，並非真實客戶。
> 本文件不包含任何真實客戶關係、真實成效數據或真實商業成果，僅用於展示
> 頁構所的網站策略、資訊架構、設計與工程執行能力。

## 概念客戶背景

鋒岳自動化是一家設定於台灣中部的虛構 B2B 自動化設備與精密運動系統供應商，
核心業務涵蓋精密線性運動模組、視覺定位檢測、自動化組裝整合、既有產線升級
與客製設備整合。目標客戶為海外設備採購人員、工廠管理者、自動化工程師與
系統整合商。

## 商業問題

工業 B2B 官網常見的問題是：內容以公司為中心而非以買主決策路徑為中心，
產品規格分散難以比較，中英文版本品質落差大，且詢價流程往往只有一個
籠統的聯絡表單，無法收集足夠資訊讓業務或工程團隊做第一輪篩選與評估。

## 客群

三種主要買主路徑：

1. 海外採購人員（搜尋、展覽、業務信件進站，需要快速確認能力與提交 RFQ）
2. 自動化／製程工程師（需要規格細節、適用情境、下載資料）
3. 企業決策者（需要理解定位與合作流程再決定是否接洽）

## 資訊架構

十個頁面群組、雙語（zh-TW／en）平行路由：首頁、解決方案（總覽 + 6 個方案，
其中 1 個完整深度詳細頁）、產品（總覽 + 3 個產品皆有完整規格頁）、產業應用
（總覽 + 4 個產業，其中 1 個完整深度詳細頁）、關於我們、技術資源（2 篇
實用文章）、聯絡與 RFQ、404。內容以 Astro Content Collections 結構化管理
（Zod Schema 驗證），而非分散寫死於頁面中，確保規格、方案、產業之間的
交叉引用（相關產品、相容方案）可維護且不會產生內容漂移。

## 轉換策略

雙層 CTA 設計：主要 CTA「提交專案需求」導向完整 RFQ 表單，次要 CTA
「索取技術建議」降低尚未準備好提交完整需求的訪客的行動門檻。RFQ 表單
收集公司、職稱、產業、專案類型、預算區間、時程、是否已有規格、是否需要
保密協議等欄位，讓業務與工程團隊在第一次聯繫前就能做初步篩選與評估，
而非只收到一句「請聯絡我」。

表單同時實作雙模式（正式 API／Demo Mode），Demo Mode 下完整執行前端驗證，
但明確標示不會實際送出資料，避免作品集展示產生誤導性的「已送出成功」假象。

## 設計方向

視覺定位為「精密是可以被看見的過程，而不是需要被相信的宣稱」：以工程圖紙
的秩序感（網格、留白紀律、資料化的規格表）取代常見的科技新創漸層或
賭場式黑金工業感樣板。色彩策略採用 Restrained（中性色 + 單一銅橘強調色），
刻意避開 AI 生成介面常見的紫藍漸層與過度玻璃擬態。完整決策記錄於
`DESIGN.md` 與 `docs/DESIGN_SYSTEM.md`。

## 技術方案

Astro + TypeScript Strict 靜態生成，零前端框架（原生 JavaScript 處理
互動），CSS Custom Properties 管理 Design Token，Content Collections
管理結構化內容。技術選型完整記錄於 `docs/PROJECT_BRIEF.md`。

## 效能處理

靜態 HTML 優先、最少 JavaScript、全站圖像為向量 SVG（無點陣圖載入成本）、
無阻塞第三方腳本（Analytics 僅在環境變數提供 ID 時才注入）。實際
Lighthouse 分數未在本次無瀏覽器沙盒環境中實測，誠實記錄於
`docs/QA_CHECKLIST.md`「已知限制」。

## SEO

每頁獨立 Meta Title／Description、Canonical、hreflang、Open Graph、
語意化 HTML、Breadcrumb、動態 Sitemap／Robots.txt，結構化資料僅在內容
真正符合時輸出（例如 FAQPage 僅用於真正有 FAQ 內容的頁面）。

## 無障礙

Skip Link、可見 Focus 狀態、表單錯誤 ARIA 關聯、鍵盤可完整操作的導覽與
表單、`prefers-reduced-motion` 支援。未執行正式人工稽核，因此不對外宣稱
完全符合 WCAG 2.2 AA，誠實揭露於 `docs/QA_CHECKLIST.md`。

## 最終成果

**本概念案例的「成果」是可交付、可測試的完整網站本身，而非任何營收、
轉換率或排名數據**——後者在真實客戶關係之外編造會違反本專案的誠信原則。
可驗證的具體產出：48 個靜態頁面、0 個 TypeScript／Build 錯誤、0 個失效
內部連結、完整雙語內容、結構化資料、可運作的雙模式 RFQ 表單，以及
13 份交付文件（見 `README.md` 專案文件清單）。
